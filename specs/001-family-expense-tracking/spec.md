# Feature Specification: 家庭共享支出平台 - 核心記帳與統計功能

**Feature Branch**: `[001-family-expense-tracking]`

**Created**: 2026-08-08

**Status**: Draft

**Input**: User description: "家庭共享支出平台，第一階段核心功能（僅描述功能與使用者故事，不涉及技術實作）：

1. 使用者可建立一個「家庭群組」，並邀請其他成員加入。
2. 家庭成員可預先建立支付帳戶（例如現金、銀行帳戶、信用卡），並可新增一筆支出紀錄，包含分類、金額、日期（預設當天當下）、支付帳戶。
3. 成員可查看家庭內所有支出紀錄列表，並可依分類或成員篩選。
4. 系統提供基本統計：依分類、依成員的支出總計（例如本月各類別花費、各成員分攤金額）。
5. 通知功能：
   a. 每月固定時間，系統自動透過 LINE 通知家庭成員當月支出匯總。
   b. 成員可透過 LINE 傳送關鍵字，主動查詢指定月份的支出匯總。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立家庭群組並邀請成員 (Priority: P1)

使用者首次使用本平台時，建立一個屬於自己家庭的群組，並邀請其他家庭成員加入，成為後續所有記帳與統計功能的基礎。

**Why this priority**: 若無法建立家庭群組並讓成員加入，其餘所有功能（記帳、查詢、統計、通知）都無法運作，是整個系統的先決條件。

**Independent Test**: 可獨立測試——使用者建立家庭群組後，邀請另一位使用者加入，驗證雙方皆能看到彼此屬於同一個家庭群組。

**Acceptance Scenarios**:

1. **Given** 使用者尚未加入任何家庭群組，**When** 使用者建立一個新的家庭群組並命名，**Then** 系統建立該群組，且該使用者成為此群組的成員（建立者）。
2. **Given** 使用者已建立家庭群組，**When** 使用者邀請另一位使用者加入，**Then** 被邀請者可接受邀請並成為該家庭群組的成員。
3. **Given** 一位使用者已是某家庭群組成員，**When** 該使用者嘗試建立或加入另一個家庭群組，**Then** 系統依照家庭群組歸屬規則處理（見 Assumptions）。

---

### User Story 2 - 建立支付帳戶並記錄支出 (Priority: P1)

家庭成員預先建立自己會使用的支付帳戶（如現金、銀行帳戶、信用卡），並在日常消費後新增一筆支出紀錄，記錄分類、金額、日期與使用的支付帳戶。

**Why this priority**: 這是本平台的核心價值——記帳，沒有支出資料，後續的查詢、篩選、統計、通知都無從談起。

**Independent Test**: 可獨立測試——成員建立一個支付帳戶後，新增一筆支出紀錄，驗證該紀錄正確包含分類、金額、日期與支付帳戶，且日期預設為當下。

**Acceptance Scenarios**:

1. **Given** 成員已加入家庭群組，**When** 成員新增一個支付帳戶（如「現金」），**Then** 系統儲存該支付帳戶並可供後續支出紀錄選用。
2. **Given** 成員已建立至少一個支付帳戶，**When** 成員新增一筆支出紀錄並選擇分類、輸入金額、選擇支付帳戶（未指定日期），**Then** 系統以當天當下時間作為該筆支出的日期並成功儲存。
3. **Given** 成員新增支出紀錄時，**When** 成員手動指定一個非當下的日期，**Then** 系統以成員指定的日期儲存該筆支出。
4. **Given** 成員新增支出紀錄，**When** 金額為 0 或負數，或必填欄位（分類、支付帳戶）未填寫，**Then** 系統拒絕儲存並提示錯誤。

---

### User Story 3 - 查看與篩選家庭支出紀錄 (Priority: P2)

家庭成員可查看家庭內所有成員的支出紀錄列表，並依分類或依成員篩選，以了解家庭整體或特定面向的花費狀況。

**Why this priority**: 建立在記帳功能之上，讓已記錄的資料產生「可被查看、可被篩選」的價值，是統計功能的前置需求。

**Independent Test**: 可獨立測試——在家庭中已有多筆不同成員、不同分類的支出紀錄後，成員切換分類篩選與成員篩選，驗證列表結果正確對應篩選條件。

**Acceptance Scenarios**:

1. **Given** 家庭群組內已有多筆支出紀錄，**When** 成員開啟支出紀錄列表，**Then** 系統顯示家庭內所有成員的支出紀錄（不僅限自己新增的）。
2. **Given** 成員正在查看支出紀錄列表，**When** 成員選擇特定分類進行篩選，**Then** 列表僅顯示該分類的支出紀錄。
3. **Given** 成員正在查看支出紀錄列表，**When** 成員選擇特定成員進行篩選，**Then** 列表僅顯示該成員新增的支出紀錄。
4. **Given** 成員同時套用分類與成員篩選，**When** 兩個條件皆設定，**Then** 列表顯示同時符合兩個條件的支出紀錄。

---

### User Story 4 - 查看基本統計 (Priority: P2)

家庭成員可查看依分類與依成員彙總的支出統計，例如本月各類別花費、各成員分攤金額，以掌握家庭整體財務狀況。

**Why this priority**: 在有記錄與篩選功能後，統計提供更高層次的彙總資訊，是本平台區別於單純記帳本的核心加值功能，但仍依賴前述功能先行完成。

**Independent Test**: 可獨立測試——在家庭中已有本月多筆不同分類、不同成員的支出紀錄後，開啟統計頁面，驗證各分類總計與各成員總計金額正確加總。

**Acceptance Scenarios**:

1. **Given** 家庭本月已有多筆不同分類的支出紀錄，**When** 成員查看統計，**Then** 系統顯示本月依分類彙總的支出總計，且各分類金額加總等於本月總支出。
2. **Given** 家庭本月已有多筆不同成員新增的支出紀錄，**When** 成員查看統計，**Then** 系統顯示本月依成員彙總的支出總計，且各成員金額加總等於本月總支出。
3. **Given** 家庭本月尚無任何支出紀錄，**When** 成員查看統計，**Then** 系統顯示總計為零，而非錯誤或空白畫面。

---

### User Story 5 - 每月自動 LINE 通知支出匯總 (Priority: P3)

系統於每月固定時間，自動透過 LINE 主動通知家庭成員當月的支出匯總，讓成員不需主動開啟平台即可掌握家庭花費狀況。

**Why this priority**: 屬於錦上添花的主動提醒功能，建立在統計功能之上，即使沒有此功能，成員仍可手動查看統計，故優先度低於前述核心記帳與查看功能。

**Independent Test**: 可獨立測試——設定好家庭成員的 LINE 通知對象後，於系統排定的月結時間點觸發通知流程，驗證每位已綁定 LINE 的成員皆收到當月支出匯總訊息。

**Acceptance Scenarios**:

1. **Given** 家庭成員已完成 LINE 通知綁定，**When** 到達系統設定的每月固定通知時間，**Then** 系統自動發送當月（統計截至發送當下）的支出匯總訊息給該成員的 LINE。
2. **Given** 某成員尚未完成 LINE 通知綁定，**When** 到達月結通知時間，**Then** 系統不會嘗試發送通知給該成員，也不影響其他已綁定成員收到通知。
3. **Given** 家庭當月尚無任何支出紀錄，**When** 到達月結通知時間，**Then** 系統仍發送通知，內容顯示本月支出為零。

---

### User Story 6 - 透過 LINE 關鍵字主動查詢月支出匯總 (Priority: P3)

家庭成員可主動透過 LINE 傳送關鍵字，查詢指定月份（含當月或過去月份）的家庭支出匯總，不需等待每月固定通知。

**Why this priority**: 屬於便利性的主動查詢功能，與每月自動通知同屬通知模組的延伸，優先度與 User Story 5 相當，皆晚於核心記帳與統計功能。

**Independent Test**: 可獨立測試——已綁定 LINE 的成員透過 LINE 傳送指定月份的查詢關鍵字，驗證系統回覆該月份正確的支出匯總內容。

**Acceptance Scenarios**:

1. **Given** 成員已完成 LINE 通知綁定，**When** 成員透過 LINE 傳送查詢指定月份支出的關鍵字訊息，**Then** 系統回覆該月份的支出匯總（依分類與依成員彙總）。
2. **Given** 成員查詢的月份尚無任何支出紀錄，**When** 系統處理查詢，**Then** 系統回覆該月支出為零，而非無回應或錯誤訊息。
3. **Given** 傳送訊息的 LINE 帳號尚未綁定任何家庭成員身分，**When** 系統收到查詢關鍵字，**Then** 系統回覆提示該帳號尚未綁定，而非洩漏任何家庭的支出資料。

---

### Edge Cases

- 家庭群組建立者若為唯一成員且欲離開群組，系統應如何處理（群組是否解散、是否需先轉移建立者身分）？
- 支付帳戶若已有關聯的支出紀錄，成員刪除或停用該帳戶時，既有支出紀錄應如何顯示（保留歷史紀錄但標示帳戶已停用）。
- 篩選條件（分類或成員）對應的資料在系統中已不存在（例如成員已離開家庭）時，篩選結果與歷史紀錄應如何呈現。
- 統計月份的邊界如何定義（以自然月 1 日至月底計算，或以其他週期）。
- 月結通知發送當下若家庭尚無任何已綁定 LINE 的成員，系統應如何處理（略過發送，不視為錯誤）。
- 同一 LINE 帳號嘗試綁定至多個家庭成員身分時的處理方式。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 允許使用者建立一個新的家庭群組，並將建立者自動列為該群組成員。
- **FR-002**: 系統 MUST 允許家庭群組成員邀請其他使用者加入該家庭群組。
- **FR-003**: 系統 MUST 允許家庭成員建立支付帳戶，並至少支援「現金」「銀行帳戶」「信用卡」等類型的自訂命名。
- **FR-004**: 系統 MUST 允許家庭成員新增支出紀錄，紀錄須包含分類、金額、日期時間、所使用的支付帳戶、以及新增者身分。
- **FR-005**: 系統 MUST 在成員新增支出紀錄未指定日期時，預設使用當下的日期與時間。
- **FR-006**: 系統 MUST 允許成員在新增支出紀錄時手動指定非當下的日期。
- **FR-007**: 系統 MUST 提供家庭內所有支出紀錄的列表，且成員可查看家庭內其他成員新增的支出紀錄。
- **FR-008**: 系統 MUST 允許成員依分類篩選支出紀錄列表。
- **FR-009**: 系統 MUST 允許成員依成員篩選支出紀錄列表。
- **FR-010**: 系統 MUST 允許分類與成員篩選條件同時套用。
- **FR-011**: 系統 MUST 提供依分類彙總的支出統計（例如本月各分類花費總計）。
- **FR-012**: 系統 MUST 提供依成員彙總的支出統計（例如本月各成員分攤金額）。
- **FR-013**: 系統 MUST 於每月固定時間，自動透過 LINE 通知已完成 LINE 綁定的家庭成員當月支出匯總。
- **FR-014**: 系統 MUST 允許成員透過 LINE 傳送關鍵字，查詢指定月份的家庭支出匯總。
- **FR-015**: 系統 MUST 確保 LINE 查詢僅回覆給已綁定家庭成員身分的 LINE 帳號，未綁定帳號不得取得任何家庭支出資料。
- **FR-016**: 系統 MUST 拒絕金額為零或負數、或缺少必填欄位（分類、支付帳戶）的支出紀錄。
- **FR-017**: 系統 MUST 確保支出紀錄與統計資料僅在同一家庭群組內可見，不同家庭群組之間的資料須互相隔離。

### Key Entities

- **家庭群組 (Family Group)**：代表一個共享支出資料的家庭單位，具有名稱與成員清單；是所有支付帳戶、支出紀錄與統計資料的歸屬範圍。
- **成員 (Member)**：使用者在某個家庭群組中的身分，可建立支付帳戶、新增支出紀錄、查看家庭內所有紀錄與統計；可選擇綁定 LINE 帳號以接收通知與查詢。
- **支付帳戶 (Payment Account)**：成員預先建立的付款來源（例如現金、銀行帳戶、信用卡），供新增支出紀錄時選用。
- **支出紀錄 (Expense Record)**：一筆消費紀錄，包含分類、金額、日期時間、所屬支付帳戶、新增者（成員）與所屬家庭群組。
- **分類 (Category)**：支出紀錄所屬的消費類別，用於篩選與統計彙總。
- **月支出統計 (Monthly Summary)**：依分類與依成員彙總特定月份支出金額的彙總結果，供列表統計畫面與 LINE 通知/查詢共用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者可在 3 分鐘內完成建立家庭群組並成功邀請至少一位成員加入。
- **SC-002**: 成員可在 30 秒內完成新增一筆支出紀錄（含選擇分類與支付帳戶）。
- **SC-003**: 家庭支出列表在套用分類或成員篩選後，2 秒內顯示正確篩選結果。
- **SC-004**: 統計頁面顯示的分類總計、成員總計，與該月所有支出紀錄加總金額 100% 一致。
- **SC-005**: 每月固定通知時間後 5 分鐘內，所有已綁定 LINE 的家庭成員皆收到當月支出匯總訊息。
- **SC-006**: 成員透過 LINE 傳送查詢關鍵字後，1 分鐘內收到指定月份的支出匯總回覆。
- **SC-007**: 90% 的新使用者無需額外說明，即可獨立完成「建立家庭群組 → 新增支付帳戶 → 新增一筆支出」的完整流程。

## Assumptions

- 家庭群組與成員為多對多以外的簡化模型：本階段假設一位使用者僅屬於一個家庭群組；若使用者已屬於某家庭群組，暫不支援其加入或建立第二個家庭群組。
- 分類清單於本階段採用系統預先定義的一組常用分類（如飲食、交通、居住、娛樂、醫療、其他），成員新增支出時從中選擇；自訂分類不在本階段範圍內。
- 每月固定通知時間由系統統一設定（非各家庭可自訂），本階段所有家庭共用同一個月結通知時間點。
- 統計與通知的「月份」以自然月（每月 1 日至月底）為計算區間。
- 支出紀錄一旦新增後，本階段預設支援成員編輯或刪除紀錄，但僅限本人新增的紀錄；家庭群組建立者可管理群組成員但不預設擁有編輯他人支出紀錄的權限（詳見待釐清事項）。
- LINE 為本階段唯一的主動通知與查詢管道，暫不支援 Email、簡訊或站內推播通知。
- 支付帳戶為家庭成員個人層級建立（非家庭共用帳戶清單），但新增的支出紀錄與其彙總結果仍在整個家庭群組內共享可見。
